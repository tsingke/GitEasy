# 工作区、索引与提交：辅导材料

## 实验拓展：把一个修改拆成两个可解释的提交
### 任务背景与提交边界
课程说明中既有实验地点，又有参考资料链接。地点调整与链接纠错属于两个独立决定：前者需要通知学生，后者只修正阅读入口。如果将二者合为一项提交，日后只撤销地点调整时就必须重新筛选内容。索引使我们可以在一次编辑之后，按任务意图组织提交。

本实验采用两个文件，先让提交边界变得直观；掌握后再迁移到同一文件中的部分暂存。所有步骤在新建的 `split03` 中完成。首次提交建立基线，后两次提交分别记录地点与链接的变化。


### 建立具有两个独立任务的基线

```bash
mkdir split03
cd split03
git init -b main
git config user.name "Git Learner"
git config user.email "learner@example.invalid"
printf 'Room: A101\n' > room.txt
printf 'Guide: https://example.invalid/old\n' > links.txt
git add room.txt links.txt
git commit -m "docs: establish course information"
printf 'Room: B202\n' > room.txt
printf 'Guide: https://example.invalid/guide\n' > links.txt
git diff --stat
git add room.txt
git diff --cached --name-only
git diff --name-only
```


此时已暂存差异应只包含 `room.txt`，未暂存差异应只包含 `links.txt`。判断依据不是编辑顺序，而是索引中目前选择了什么内容。若输出同时出现两个文件，应停止提交，先核对暂存范围。


### 分别提交，并核对各自的变化

```bash
git commit -m "docs: move the course to room B202"
git diff HEAD^ HEAD --name-only
git add links.txt
git commit -m "docs: correct the reading guide link"
git log -3 --oneline
git diff HEAD^ HEAD --name-only
test -z "$(git status --porcelain)"
test "$(git rev-list --count HEAD)" = 3
```


最后的历史应有三个提交。第一项是基线，第二项只改变地点，第三项只改变链接。可以用每项提交与其父提交的比较证明边界，而不能仅凭提交说明作判断。说明写得准确，仍可能因误暂存而包含额外内容。

## 文本、编码与换行的背景
### 文件看起来相同，为何仍有差异
文本编辑器展示的是字符和布局，Git 比较的是经过相关属性处理后的内容。行尾方式、文件末尾换行、制表符与空格、字符编码，都可能造成肉眼不容易察觉的差异。出现整篇文件被重写的补丁时，应先检查这些因素，再判断是否发生了大规模语义修改。

LF 和 CRLF 是两种常见行尾形式。跨平台项目可以通过属性规则约定仓库中的规范化方式，但规则需要与现有文件状态共同考虑。不能在不检查差异的情况下直接进行全仓库转换，否则格式调整会混入功能修改，削弱后续检索与评审的效果。第 14 章将进一步讨论仓库属性。

### 二进制文件也可以跟踪，但可读性不同
Git 能保存许多类型的文件，并不只限于程序源码。然而，对图像、压缩包或办公文档，文本补丁通常不能直接展示语义变化。即使文件成功提交，评审者仍可能需要专用比较工具或导出的预览资料。

因此，选择资料格式时应同时考虑编辑需求和协作可读性。例如正文采用可审阅的文本源文件，图片保留可编辑源与导出结果，并在提交说明中交代两者的对应关系。版本控制的存储能力与人能否理解变化，是两个不同的问题。

## 状态分析：删除、忽略与停止跟踪
### 删除文件是一项可以记录的变化
已经跟踪的文件从工作区消失后，Git 可以把删除作为差异展示。若确实需要从下一版中移除，应将删除纳入索引并提交；若只是误删，应从明确来源恢复。看到删除状态就立即恢复，或看到文件不存在就认定历史丢失，都忽略了工作区与提交快照之间的区别。

### 忽略规则作用于候选发现
忽略规则主要减少未跟踪文件进入日常候选的干扰。它不删除已提交历史，也不会自动停止跟踪既有文件。假设 `local.conf` 已经入库，后来写入忽略规则，旧版本和当前索引仍可能包含它。只有明确改变跟踪状态并提交，后续版本才会体现这种选择。

如果该文件曾含有效凭据，停止跟踪也不足以完成事故处置。应先撤销或轮换凭据，再评估传播范围与历史清理。第 15 章将展开处理流程。本章需要掌握的是：文件发现规则、当前版本内容与历史中已有内容，分别属于不同层次。

## 迁移练习：设计一项能够独立撤销的提交
请为课程项目设计三项修改：调整时间、修正文句、增加一份参考资料。说明哪些修改应合并，哪些应拆分，并用补丁验证提交范围。允许不同答案，但每个边界都应能够由同一目的解释。

参考分析：时间调整与相应通知文档可能应共同提交，因为两者必须保持一致；无关文句修正可独立提交；新增参考资料若只是支持时间调整的附件，则还需考虑其依赖关系。合理边界不等于机械追求“一次只改一行”，而是使每项提交形成可以理解、评审和验证的完整变化。
