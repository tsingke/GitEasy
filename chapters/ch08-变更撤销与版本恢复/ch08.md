# 变更撤销与版本恢复：辅导材料

## 纠错决策：先保留什么，再选择命令
### 恢复目标必须具体
“回到昨天”至少可能表示三种任务：查看昨天提交中的文件；让当前工作文件恢复为某一状态；在共享历史中撤销昨天引入的一项变化。三者的输入、影响范围和协作后果都不同。选择命令前，先把目标改写为“保留哪些现有成果，改变哪些状态”。

例如错误只在未提交的工作文件中，而已暂存内容仍然正确，应优先考虑从索引恢复特定路径。若错误提交已经被其他成员使用，则通常应讨论追加修正，而不是直接移动公共分支。若只是需要取出旧文件的一段内容，可以先查看或导出，再作局部编辑，不必让整个项目退回旧位置。

### 把草稿与历史分别保全
恢复操作经常围绕提交对象展开，但现场还可能包含未跟踪文件、索引中的候选和编辑器尚未保存的内容。提交级备份入口不能覆盖这些全部状态。应根据现场分别保存必要草稿，并记录当前分支、提交和操作状态。

对重要项目，先复制现场或创建可信副本，再在副本上调查，会降低继续写入造成的干扰。保全不等于随意执行清理命令；清理可能删除恢复所需对象或工作文件。是否能恢复，应由实际存在的对象和副本决定。

## 实验拓展：撤销错误，保留后续正确变化
本实验建立三个提交：基线、错误的地点调整、正确的阅读说明。目标是撤销地点调整，同时保留后续阅读说明，并让公共历史仍可追溯。


### 建立包含错误和后续成果的历史

```bash
mkdir correction08
cd correction08
git init -b main
git config user.name "Git Learner"
git config user.email "learner@example.invalid"
printf 'Room: A101\n' > room.txt
git add room.txt
git commit -m "docs: establish the course room"
printf 'Room: Wrong\n' > room.txt
git add room.txt
git commit -m "docs: change the room incorrectly"
BAD08=$(git rev-parse HEAD)
printf 'Read the staged diff before committing.\n' > guide.txt
git add guide.txt
git commit -m "docs: add the review guide"
git revert --no-edit "$BAD08"
```



### 证明错误被撤销，而后续成果与历史仍保留

```bash
git log -4 --oneline
git show HEAD:room.txt
git show HEAD:guide.txt
git merge-base --is-ancestor "$BAD08" HEAD
test "$(git rev-list --count HEAD)" = 4
grep -q 'Room: A101' room.txt
grep -q 'Read the staged diff' guide.txt
test -z "$(git status --porcelain)"
```


结果有四项提交。错误提交仍是当前历史的祖先，说明撤销没有删除它；新增提交抵消其内容变化，阅读说明则继续存在。若把分支直接移回基线，后续正确成果的入口也会受到影响，因此不能把两种做法视为等价。

## 恢复线索的可信度与生命周期
### reflog 是本地线索，而非永久保险
reflog 记录某些本地引用的更新，可为误移动后的定位提供帮助。但不同仓库的记录可能不同，记录也有保留与过期条件。新克隆通常不能取得另一台计算机的全部本地 reflog，因此应尽早调查，不应将它作为唯一备份。

找到疑似目标后，应先核对文件内容、父关系和提交说明，再建立清晰的保存入口。短标识或时间描述可能不足以唯一定位，特别是在多条相近历史并存时。保存入口以后，再决定怎样把成果整合回正常工作线。

### 没有进入 Git 的内容可能无法由 Git 找回
如果某段编辑从未暂存、提交或以其他方式写入 Git 对象库，Git 不一定保存过它。此时应检查编辑器历史、系统备份或其他副本。即使发现不可达对象，也需要判断对象类型和内容，不能承诺每次误删都有完整恢复路线。

本章强调恢复边界，是为了帮助读者建立日常保全习惯。及时形成有意义的提交、定期验证备份、对高影响操作先明确范围，比事后依赖偶然线索更可靠。

## 迁移练习：为三种现场分别制定方案
现场甲：只有工作区出现误改；现场乙：本地提交错误且尚未分享；现场丙：共享分支已包含错误，另有成员继续开发。请分别说明保留目标、查询证据和纠错策略。答案应写出为什么适用，而不仅列出命令名称。

参考分析：甲重点是选择正确内容来源与路径；乙允许在保全后整理本地历史，但仍须保留需要的草稿；丙需要考虑其他成员依赖，通常优先追加修正并完成协作说明。若错误涉及凭据，三种现场都应先处理凭据有效性，再讨论历史呈现。
