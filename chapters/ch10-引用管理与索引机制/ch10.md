# 引用管理与索引机制：辅导材料

## 实验拓展：索引树与工作文件可以不同
### 从“暂存列表”走向内容模型
把索引仅理解为文件名清单，会难以解释暂存后再次编辑的情况。索引记录候选路径及相应对象信息，因而可以生成下一次提交所需的树。工作区文件后来变化，并不会自动改写已经选择的候选内容。

下面的独立实验使用 `write-tree` 将索引状态写成树对象，但不立即提交。这样能够把“形成候选树”与“创建提交并更新分支”两个步骤分开观察。底层命令用于理解模型，日常提交仍优先使用高层命令。


### 先暂存，再编辑，分别读取两份内容

```bash
mkdir candidate10
cd candidate10
git init -b main
git config user.name "Git Learner"
git config user.email "learner@example.invalid"
printf 'Version: one\n' > note.txt
git add note.txt
TREE10=$(git write-tree)
printf 'Version: two\n' > note.txt
git show "$TREE10:note.txt"
cat note.txt
git diff -- note.txt
git commit -m "docs: record the selected first version"
test "$(git rev-parse HEAD^{tree})" = "$TREE10"
test "$(git show HEAD:note.txt)" = 'Version: one'
grep -q 'Version: two' note.txt
```


提交中的树与先前从索引写出的树相同，而工作文件仍是第二版。此时提交成功，但工作区并不干净。这不是 Git 漏掉了保存，而是提交忠实记录了已经选择的候选状态。


### 重新选择内容以后，树才发生变化

```bash
git add note.txt
NEXT10=$(git write-tree)
test "$NEXT10" != "$TREE10"
git commit -m "docs: record the revised second version"
test "$(git rev-parse HEAD^{tree})" = "$NEXT10"
test -z "$(git status --porcelain)"
```


该实验把一次常见误解转化为可验证事实：编辑器保存只更新工作文件，暂存才更新相应候选；创建提交再把候选树连接进历史。理解这条链路以后，检查候选差异就成为提交前的必要步骤，而非可有可无的仪式。

## 引用更新与并发条件
### 为什么需要期待的旧值
两个程序可能同时准备更新同一引用。若第二个程序不核对旧值，便可能覆盖第一个程序刚完成的进展。带旧值条件的更新表达的是：“只有当前值仍等于我观察到的值，才执行这次替换。”这是对并发变化的一种约束，不是对新提交内容的质量判断。

类似思想也出现在带租约的推送中。它有助于避免覆盖未被预期的远端更新，但不能代替团队对改写共享历史的授权。机械满足旧值条件，并不意味着历史替换符合业务约定。

### 不依赖引用的物理布局编写脚本
分支引用可能采用不同存储形式，HEAD、公共目录和工作树专属信息也各有边界。脚本应优先使用 `rev-parse`、`symbolic-ref` 和 `for-each-ref` 等接口，不应把读取某个固定文件路径当作普遍规则。

同样，不能假设 `.git` 必然是目录。在关联工作树或某些嵌套情境中，它可以是指向实际管理目录的文本文件。直接拼接 `.git/objects` 或 `.git/HEAD` 的脚本，可能只在最简单的仓库布局中工作。

## 名称解析的实务边界
### 路径与修订名称可能发生歧义
同一个字符串可能既是分支名，又是文件路径。命令需要按照各自语法解释参数；在适当位置使用 `--` 可以明确后续参数是路径。脚本还应尽量使用完整引用名或验证过的对象表达式，减少环境差异造成的歧义。

对于来自外部输入的名称，除了加引号，还要考虑它是否可能被当作命令选项或非法修订。引号处理终端分词，并不会自动证明输入具有合法的 Git 语义。应按命令接口逐层验证。

### 让诊断结果服务于下一步决定
一次好的诊断应回答：当前 HEAD 关联哪个位置，候选树是否符合预期，工作文件是否另有编辑，是否存在未完成操作。只输出大量标识却不解释关系，会增加阅读负担。报告可以保留关键查询，并在每项结果后写出它排除了哪一种误判。

迁移练习：某脚本把分支移动到正确提交后，工作文件仍旧。请解释原因。参考分析是：引用更新与工作区更新属于不同动作；正确的分支标识不能证明目录内容已随之改变。应先保护现场，再选择与目标状态匹配的高层操作，不能靠重复更新引用解决文件差异。
