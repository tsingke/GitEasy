# 仓库规模、依赖与工作树：辅导材料

## 案例研读：为仓库增长选择合适方案
### 先测量瓶颈，再选择工具
课程仓库逐年增加高清图片、实验数据和历史资料，首次取得越来越慢。此时应先区分成本来自哪里：网络传输、历史对象、工作区文件数、外部依赖，还是构建过程。不同成本对应不同工具，不能把“仓库大”视为单一问题。

如果只需编辑少量目录，稀疏检出可以减少工作区范围；如果历史对象本身占用较多，部分克隆或浅克隆可能改变获取成本，但会带来后续取对象或历史边界限制；如果主要是大二进制文件，则需评估 LFS 或独立数据存储，并确认服务端支持与配额。

### 方案必须覆盖新成员和离线情境
某项配置在作者计算机上运行顺利，并不能证明新成员能够取得全部材料。应从一个干净目录重新演练获取、依赖准备、构建和验证。若需要登录、联网或额外下载，应明确记录。把这些前提隐藏在个人环境中，会使项目难以交接。

对于课堂机房，还要考虑网络不稳定和账号权限。可以预先分发经过验证的资料包，但应说明包中是否包含历史、外部数据和依赖。离线材料的方便性不能代替版本对应关系。

## 实验拓展：并行目录如何保持独立
本实验使用多工作树保留主线草稿，同时在另一目录修订稳定基线。它不复制整个对象库，且两个目录中的工作文件互不覆盖。


### 创建主线与独立维护目录

```bash
mkdir parallel14
cd parallel14
git init -b main
git config user.name "Git Learner"
git config user.email "learner@example.invalid"
printf 'Room: A101\n' > room.txt
git add room.txt
git commit -m "docs: establish the stable baseline"
printf 'Unfinished optional lesson\n' > draft.txt
git worktree add -b maintenance ../maintenance14 HEAD
git -C ../maintenance14 config user.name "Git Learner"
git -C ../maintenance14 config user.email "learner@example.invalid"
printf 'Room: B202\n' > ../maintenance14/room.txt
git -C ../maintenance14 add room.txt
git -C ../maintenance14 commit -m "fix: correct the maintenance room"
```



### 核对工作文件隔离与对象共享的结果

```bash
git worktree list
grep -q 'Room: A101' room.txt
grep -q 'Room: B202' ../maintenance14/room.txt
test -f draft.txt
test ! -e ../maintenance14/draft.txt
test "$(git rev-parse main)" != "$(git rev-parse maintenance)"
git show maintenance:room.txt
git worktree remove ../maintenance14
test -f draft.txt
```


维护提交可以从主工作树查询，因为对象与引用具有共享关系；主工作目录中的 room.txt 没有自动改变，因为当前分支与工作文件状态独立。删除干净的维护工作树目录，也不会删除维护分支所指向的提交。本例中的未跟踪草稿始终保留在主目录。

## 依赖管理的复现责任
### 固定提交只是起点
子模块记录依赖提交，有助于明确版本，但依赖仓库还必须可访问，所需对象也必须能够取得。若依赖被删除或权限改变，父项目中的提交标识本身不能提供实际内容。重要交付应评估依赖镜像、许可、归档与恢复方案。

采用 subtree 时，依赖内容进入普通目录，获取路径更直接，但更新来源与本地修改之间的关系仍需维护。两种方式各有成本；不能仅以命令数量判断长期维护难度。

### 属性规则应纳入团队约定
换行、二进制判定、差异驱动和合并驱动可能影响协作体验。适合项目的规则应写入版本化配置，并说明外部工具要求。纯个人偏好则应避免无谓改变整个项目。引入新规则时，应单独检查规范化差异，让评审者能够辨认哪些变化来自规则调整。

迁移练习：项目含大量历史图片，但课堂只编辑当前练习目录。请分别说明减少工作区内容、减少初次对象传输和保存历史图片的方案，并写出各自局限。参考分析必须区分工作区、对象历史与外部存储，不能用一个“下载更少”的笼统目标替代三类问题。
