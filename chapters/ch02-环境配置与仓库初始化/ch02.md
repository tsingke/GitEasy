# 环境配置与仓库初始化：辅导材料

## 实验拓展：辨认目录、仓库与生效配置
### 为什么先查位置，再查设置
同一终端窗口可以先后进入多个目录，而 Git 会根据当前位置寻找仓库。编辑器中打开的项目与终端的当前目录也可能不同。因此，看到“不是 Git 仓库”的提示时，首先应确认目录；看到身份设置不符合预期时，则应进一步确认配置来源。把两类问题混在一起，容易在错误目录初始化一个并不需要的仓库。

以下是独立实验，使用新建的 `inspect02` 目录，不接续前面的学习仓库。姓名和邮箱是教学占位信息，仅写入本仓库配置。实验关注配置如何覆盖和如何查询，不涉及平台认证。


### 建立可定位的实验仓库

```bash
mkdir inspect02
cd inspect02
git init -b main
git config --local user.name "Git Learner"
git config --local user.email "learner@example.invalid"
pwd
git rev-parse --show-toplevel
git rev-parse --is-inside-work-tree
git config --show-origin --get user.name
git -c user.name="Temporary Learner" config --get user.name
git config --get user.name
```


`pwd` 由终端解释器提供，显示当前工作目录；`--show-toplevel` 由 Git 给出工作区顶层目录，两者在仓库子目录中可能不同。`--is-inside-work-tree` 用来判断当前位置是否属于工作区，不能据其结果推断仓库是否已经有提交。最后三项查询分别观察本地配置来源、单次命令覆盖和覆盖结束后的值。

`-c` 设置只影响本次 Git 调用及其传递的相关上下文，不会把新值写回本地配置文件。最后一次查询应重新得到 `Git Learner`。若读者只看中间输出，可能误以为身份已被永久修改；通过前后对照才能证明设置的作用范围。

### 没有提交时，分支名为何仍然存在于提示中
初始化仓库后，Git 可以记录 HEAD 将指向的分支名称，但对应分支引用尚未指向任何提交。此时不能把初始化理解为已经产生一个空白版本。可以创建第一份内容，再观察提交前后的区别。


### 从尚无提交到具有历史入口

```bash
if git rev-parse --verify HEAD; then
  echo "Unexpected initial commit" >&2
  exit 1
fi
printf '# Environment notes\n' > README.md
git add README.md
git diff --cached --stat
git commit -m "docs: record the environment entry"
git rev-parse --verify HEAD
git log -1 --format='%h %s'
test -z "$(git status --porcelain)"
```


这里将第一次查询放在条件语句中，是为了明确表示预期失败，而不是忽略错误。提交前查询 HEAD 失败，提交后查询成功，说明历史入口已经从计划中的名称转变为可解析的提交。`test` 是终端命令，用退出状态检查工作区是否干净；没有输出且退出成功才符合预期。

## 环境问题的分层诊断
### 程序找不到与仓库找不到
终端提示找不到 `git`，通常意味着当前命令搜索路径中没有对应可执行程序。此时检查安装位置和终端启动方式，比重复初始化更有意义。若 Git 可以输出版本，却提示当前位置不是仓库，则说明程序启动正常，应检查目录和仓库边界。这两个层次应按先后顺序排查。

图形客户端内置的 Git 与终端 Git 可能来自不同安装路径，版本和凭据组件也可能不同。报告问题时至少记录操作系统、终端类型、Git 版本、当前目录和原始错误。截图可辅助说明，但可复制的错误文字更便于搜索和核对。

### 编辑器没有退出与提交没有完成
某些命令会启动文本编辑器并等待其退出。终端暂时没有出现新的提示符，并不意味着程序失去响应。初学者应先辨认是否进入编辑器，再按编辑器的保存退出方式完成操作。使用图形编辑器时，还要确认命令行启动器是否等待窗口关闭；否则 Git 可能在说明文件尚未编辑时继续执行。

本书在可复现实验中经常使用 `-m` 提供简短说明，以减少环境差异。但正式项目中的复杂说明仍可使用编辑器撰写。应理解两种方式服务于相同的提交信息输入过程，而不是认为 `-m` 是提交的必要条件。

### 认证失败与提交身份错误
`user.name` 和 `user.email` 影响提交元数据，不提供服务器访问凭据。访问私有仓库时，服务器还会根据连接方式检查令牌、SSH 密钥或其他凭据。把邮箱改成平台账号邮箱，可能有助于平台关联展示，但不能据此获得读取或推送权限。

排查时先判断失败发生在哪个阶段：本地提交尚未创建，还是远程访问被拒绝。前者检查身份与编辑器，后者检查地址、连接协议、账号和授权范围。错误发生层次不同，修复措施也应不同。
