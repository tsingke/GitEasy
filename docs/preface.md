# 前言

软件贯穿现代工程系统的设计、运行与持续演进。面向教育强国建设和新工科人才培养的要求，计算机类专业教育需要把程序设计能力与工程思维、协作能力和质量意识贯通起来。学生应能实现功能、说明变化依据、组织团队协作，并验证与交付成果。版本控制是这一培养过程中的基础环节：它使修改成为可以比较和追溯的记录，使协作形成可以检查的过程，也使工程责任落实到具体的内容与决策。

Git于2005年围绕Linux内核协作开发的需要而诞生。分布式仓库、内容寻址、轻量分支和灵活的历史整合机制，使它能够支持从个人练习到大型开源项目的多种工作方式。随着代码托管、自动检查和开源协作的发展，Git的应用已延伸到程序、文档、配置与研究资料等领域。理解Git，有助于认识现代软件开发如何在持续变化中保留依据、协调分工和积累可信成果。

版本管理的难处，常常出现在看似熟悉的操作之后：文件已经保存，拟提交内容却未随之更新；抓取已经完成，当前分支却仍停留在原处；合并没有报告冲突，程序行为却偏离了需求。仅凭命令名称推测结果，容易忽略作用对象和成立条件。本书从这些具体问题出发，先说明数据与关系，再安排操作与验证，引导读者形成能够解释现象、判断边界并迁移到新情境的知识结构。

本书主要面向高等学校计算机类及相关专业本科生，可用于版本控制、软件工程实践和开源协作课程，也适合结合程序设计课程开展实验。基础部分从文件、目录、路径及终端操作讲起，无需版本控制基础。前期使用简短的课程资料观察状态与历史，后期进入校园一卡通工程，在同一业务场景中逐步处理开发、协作、维护与交付问题。

全书分为基础、核心、进阶和实践四篇，共十七章。基础篇介绍版本控制思想、环境准备、提交组织与历史查询；核心篇围绕分支、合并、远程协作和变更恢复，说明独立修改如何交换、整合和纠正；进阶篇讨论对象、引用、索引、历史整理、标签与签名，把日常操作同内部机制联系起来；实践篇介绍团队工作流、仓库规模与依赖、自动检查、安全与恢复、GitHub及图形化客户端，并以综合项目贯通主要工程技能。

本书以统一的数据模型组织知识。工作文件、索引和提交树分别描述不同的内容状态，对象记录内容及关系，引用提供访问入口；命令则在明确的范围内读取或改变这些状态。讲解中把查询、操作与验证相互衔接，通过独立副本、对照实验和可重复判断呈现因果关系。学习的进展，应体现在能够说明“依据什么作出选择”与“怎样证明结果符合目标”，而不局限于复现某一次成功输出。

图示与范例服务于概念辨析。文件夹图呈现仓库数据的组织，提交图追踪父关系与名称指向，状态对照图区分相近命令的结果，工程情境图展示条件、证据与责任。各章以小结收束主要结论，以分层习题检验理解、操作与综合应用，以复习导图帮助形成联系；书后的参考答案重列题意并说明考查知识点、分析过程与验收依据，命令速查和索引提供进一步查询的入口。

校园一卡通系统是全书的连续教学工程。业务核心采用C++11和多文件模块化设计，涵盖封装、继承、多态与资源管理；Qt6界面使用相应的C++17构建目标。合成账户用于演示开卡、充值、消费、挂失、解挂与流水导出，测试用于检查金额、限额和重复请求等规则。实训依次安排并行开发、冲突处理、回归修复、维护移植、历史整理、二分定位、版本发布和独立恢复，使版本管理同软件质量要求保持联系。

宜先完成基础篇与核心篇实验，再研读内部机制和工程专题。每次实验保留起始状态、预计变化、关键输出与判断依据；结果不符时保存现场，逐项核对输入、范围与条件。开放任务允许不同实现，评价应关注需求是否满足、解释是否充分以及材料能否复核。工程实践的成熟，往往体现为对一个看似平常的操作，仍能清楚说明其前提、影响和验证方法。

配套项目GitEasy按章提供学习说明、范例、习题解析、实验脚本和校园工程源码，访问地址为https://github.com/tsingke/GitEasy。读者可通过项目的Issue提交勘误与改进建议；资源入口及可用内容以仓库说明为准。平台界面、客户端和依赖环境会持续演进，学习中应以本书说明的原理为依据，结合当前文档核对具体入口与操作要求。

本书编写过程中参阅了版本控制领域的优秀著作、技术资料和官方文档，谨向相关作者、开发者与维护者致谢。书中内容力求概念准确、论证清楚、实践可复核，仍有需要完善之处，诚请专家、教师和读者批评指正。本书尚未出版，仅供学习与交流，不得用于商业用途；教材文字、原创图表及版式的著作权归作者所有，第三方材料依其原有权利说明使用。
