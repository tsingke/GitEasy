# 学习与实验说明

## 从零开始

需要 Git、Bash、Python 3.9及以上版本。先查询 `git --version` 和 `python3 --version`。复杂实验还用到 OpenSSH签名功能以及 Git subtree；缺少工具时先按提示补齐，勿把环境失败记成实验通过。

1. 基础路径：第1—4章，建立目录、候选内容、提交与查询模型。
2. 核心路径：第5—8章，完成分支、整合、协作与纠错。
3. 原理路径：第9—12章，以对象、引用和索引解释整理与发布。
4. 工程路径：第13—16章，完成评审、规模管理、自动化和交接。

首次学习建议依次阅读。复习时可按根目录表格跳转。章末知识结构图是复习入口，不能替代首次概念讲解。

## 实验运行方式

在仓库根目录执行 `python3 tools/run_lab.py --chapter 03`。运行器读取对应章节脚本，在临时目录创建练习仓库，结束后删除练习现场，日志保存在独立证据目录中。`--list` 只列出路线；`--output` 指定一个尚不存在的证据目录。

脚本含预期冲突、拒绝或校验失败，随后用断言确认正确现场。运行结果以运行器最终状态为准；阅读日志时仍应解释每一项拒绝。所有路线只使用本地路径，不向GitHub推送。

自动运行用于核对范例，手工练习用于建立理解。手工执行前，应新建专用目录，按辅导材料逐块执行，不把脚本片段混入已有作业仓库。

## 环境与验证边界

以 `docs/verification.json` 记录的实际环境为准。CI配置会在Linux与macOS运行，不预先承诺尚未完成的结果。Windows读者可使用Git Bash阅读与手工实践，目前不据此宣称Windows全面验收。LFS服务、真实GitHub权限、分支规则、人工评审和生产凭据处置不属于离线自动验证范围。

## 线上练习

在自己的账号下派生GitEasy，确认 `origin` 指向个人仓库，`upstream` 指向作者仓库。提交任务分支，准备说明与证据，再发起PR。只有实际创建的请求和实际运行的检查才能写入报告。教材的双人本地模拟不等于线上评审已经完成。

## 新增GitHub专章与校园工程

第16章面向平台与客户端人工实践；第17章的连续演练需要CMake和C++编译器。业务核心为C++11，Qt6界面为C++17。二者分别验收，Qt环境不足不能报告界面通过。全部17章习题与218项参考答案与教材逐题对应。

当前GitEasy可能为私有仓库；克隆、fork与访问设置均依实际权限，不要求为教学改变原项目可见性。教材截图记录的是指定时间和角色看到的页面。
